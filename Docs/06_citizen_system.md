# 06. 시민 시스템 & 만족도

## 6-1. 시민 만족도 구조

각 시민은 8가지 욕구(Need)에 대한 만족도를 가집니다.

```
음식 (Food)
주거 (Housing)
보건 (Health)
유흥 (Fun)
신앙 (Faith)
직업 (Job)
자유 (Freedom)
치안 (Security)
```

이 8가지 욕구의 평균이 **종합 만족도**가 됩니다.

---

## 6-2. 만족도 계산 원리

만족도는 **빌딩 서비스**와 **정책 효과**의 합산으로 결정됩니다.

```
개별 만족도 (0~100)
= 기저값(50)
+ 건물 접근성 보정 (+/-30)
+ 칙령 일별 delta 누적
+ 이벤트/위기 패널티
+ 세금 부담 보정
```

**중요한 설계 결정**: 만족도는 즉시 바뀌지 않습니다.
- 건물을 지어도 만족도가 천천히 오릅니다.
- 칙령 해제 후에도 만족도가 천천히 내려갑니다.
- `DailyDelta`를 누적하는 방식으로 부드러운 변화를 구현합니다.

---

## 6-3. 시민 정치 성향

시민은 4개의 정치 축에서 좌/우 성향을 갖습니다.

```
EconomyAxis:              공산 ←→ 자본
ReligionMilitarismAxis:   종교 ←→ 군사
EnvironmentIndustryAxis:  환경 ←→ 산업
IntellectualAxis:         지식인 ←→ 보수
```

정치 성향은 다음 요소로 결정됩니다:
- 학력 수준 (교육 건물 접근성)
- 재산 수준 (거주지 유형, 급여)
- 직업 유형 (농업/산업/서비스업)
- 주거 형태 (무료 주택 vs 개인 소유)

---

## 6-4. NPC 정보 패널 탭 구성

시민 클릭 시 표시되는 3탭 구성입니다.

**탭 0 — 기본 (신원 + 복지)**
```
신원:
  학력: 초등/중등/대학
  재산: 하/중/상
여가 만족도:
  음식 / 보건 / 유흥 / 신앙
복지 서비스:
  주거 / 직업 / 자유 / 치안
종합 만족도: (8개 평균)
```

**탭 1 — 정치 (지지율 + 파벌)**
```
만족도 현황:
  9개 수치 (개별 8개 + 종합)
신념:
  4개 정치 축 파벌
  각 파벌별 소속 지지도
```

**탭 2 — 성향 (서술형 텍스트)**
```
신원 요약 (학력, 재산)
만족도 상태 요약
지배적 정치 성향 설명
```

## 6-5. 통근 시스템

시민은 자신의 거주지에서 직장까지 통근합니다.

```
CitizenCommuteCalc.h
  CalculateCommuteScore()  — 통근 거리/수단에 따른 점수 계산
```

통근 수단:
- 도보 (짧은 거리)
- 버스 (`BusRouteSystem` 필요)

**통근과 만족도 연결**
- 통근 시간이 길면 직업 만족도에 패널티
- 버스 노선이 있으면 더 먼 직장도 연결 가능
- 건물 배치 전략이 중요해지는 이유입니다

---

## 6-6. 이민/이주 시스템

```
SimulationSubsystem
  → 매 N 틱마다 이민자 도착 판단
  → ImmigrationRateMultiplier (칙령으로 조정 가능)
  → 인구가 늘수록 세수 증가, 노동력 증가
```

이민 증가 조건:
- 높은 평균 만족도
- 높은 임금 수준
- 특정 칙령 활성화 (`UrbanDevelopment` 등)

이민 감소 조건:
- 낮은 자유도 만족도
- 계엄령 칙령 활성화
- 치안 위기

## 6-7. 시민 통계와 알마낙 연결

시민 데이터는 알마낙(통계 백과)에 집계되어 표시됩니다.

```
알마낙 국민 페이지:
  - 연령대별 인구
  - 직업별 분포
  - 학력별 분포
  - 파벌별 분포

알마낙 만족도 페이지:
  GSatisfactionRowCount = 9
  (음식/주거/보건/유흥/신앙/직업/자유/치안/종합)
```

집계 방식:
```
WorldStatsSnapshot → 캐싱된 통계
  ↓
AlmanacDataProvider → 페이지별 데이터 준비
  ↓
AlmanacRenderer → 화면 출력
```

## 6-8. 시민 행동 버튼

시민 정보 패널에서 플레이어가 직접 행동할 수 있습니다.

```cpp
static constexpr int GCitizenActionButtonCount = 6;
```

가능한 행동 예시:
- 이 시민을 해고
- 이 시민의 직장 변경
- 이 시민에게 보조금 지급
- 이 시민 추방

이 버튼들은 `CitizenInfoInteractionService`를 통해 `GovernmentCommandService`에 명령을 전달합니다.

## 학습 포인트 요약

1. **욕구 기반 시뮬레이션**: 8개 욕구를 독립적으로 관리하면 복잡한 상호작용이 자연스럽게 생깁니다.
2. **느린 변화율**: 만족도가 즉시 바뀌지 않으면 플레이어의 실수나 성공이 시간차를 두고 나타나 게임의 긴장감이 생깁니다.
3. **통근 시스템**: 건물의 물리적 위치가 중요해져 지도 위의 전략적 배치가 의미 있어집니다.
4. **데이터 집계 파이프라인**: 개별 시민 데이터 → 스냅샷 → UI 표시의 단계적 변환이 명확합니다.
5. **행동 버튼과 서비스 레이어**: UI 버튼이 직접 데이터를 수정하지 않고 서비스를 통해 명령을 전달하면 데이터 일관성이 보장됩니다.
