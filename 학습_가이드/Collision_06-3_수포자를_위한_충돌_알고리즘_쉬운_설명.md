## 용어 설명

### 🎯 자주 나오는 용어들

#### 1. **Center (중심)**
- **뭐냐?** 도형의 한가운데 점
- **비유:** 피자의 중심점, 시계의 중심
- **왜 필요?** 도형의 위치를 알려면 중심을 알아야 함

#### 2. **HalfSize (반 크기)**
- **뭐냐?** 중심에서 끝까지의 거리
- **비유:**
  - 책상 너비가 100cm면 HalfSize.x = 50cm (중심에서 양쪽 끝까지)
  - 책상 높이가 60cm면 HalfSize.y = 30cm
- **왜 반(Half)만?** 중심 기준으로 계산하는 게 편해서

#### 3. **Axis (축)**
- **뭐냐?** 도형이 바라보는 방향
- **비유:**
  - 자동차가 북쪽을 향하고 있다 → X축이 북쪽
  - 회전하지 않은 네모 → X축은 오른쪽, Y축은 위쪽
- **왜 필요?** 도형이 회전하면 방향이 달라지니까

#### 4. **Dot (내적) - 진짜 쉽게**
- **뭐냐?** 한 벡터를 다른 방향으로 "그림자 투영"한 길이
- **비유:**
  ```
  햇빛이 비추면 막대기 그림자가 생기죠?
  막대기를 땅바닥에 투영한 길이 = 내적
  ```
- **코드:** `CenterLine.Dot(Box.Axis[X])` = CenterLine을 Box의 X축에 투영한 길이
- **실제 의미:** "이 방향으로 얼마나 멀리 있어?"

#### 5. **Cross (외적) - 진짜 쉽게**
- **뭐냐?** 두 벡터가 이루는 "회전 방향"
- **비유:**
  ```
  시계 바늘이 1시에서 3시로 가면 → 시계방향 (음수)
  시계 바늘이 3시에서 1시로 가면 → 반시계방향 (양수)
  ```
- **실제 사용:** "점 3개가 왼쪽으로 꺾이나? 오른쪽으로 꺾이나?"

#### 6. **Projection (투영)**
- **뭐냐?** 어떤 물체를 특정 방향으로 "납작하게 눌러서" 본 길이
- **비유:**
  ```
  책을 책상 위에 놓고 위에서 보면 → 책의 투영
  사람이 서 있고 햇빛이 비추면 → 그림자 = 사람의 투영
  ```

#### 7. **SAT (Separating Axis Theorem) - 분리축 정리**
- **뭐냐?** 두 물체가 안 부딪쳤는지 확인하는 방법
- **비유:**
  ```
  두 사람이 멀리 떨어져 있는지 확인하려면?
  → "가로로 봤을 때 멀리 있나?"
  → "세로로 봤을 때 멀리 있나?"
  → 둘 중 하나라도 멀리 있으면 안 부딪침!
  ```

## 1. 네모 vs 네모 충돌

### 🎨 상황 설정
```
두 개의 상자가 있어요.
부딪쳤는지 어떻게 알 수 있을까요?
```

### 📦 경우 1: 회전 안 한 네모 (AABB)

**AABB = Axis-Aligned Bounding Box = 축이 정렬된 상자**
→ 그냥 "회전 안 한 네모"라고 생각하세요!

#### 원리 (초간단 버전):
```
1. 네모A의 왼쪽 끝 vs 네모B의 오른쪽 끝 비교
   → A가 B보다 오른쪽에 있으면 안 부딪침!

2. 네모A의 오른쪽 끝 vs 네모B의 왼쪽 끝 비교
   → B가 A보다 오른쪽에 있으면 안 부딪침!

3. 위아래도 똑같이 비교

4. 모든 방향에서 안 떨어져 있으면 → 부딪침!
```

#### 생활 예시:
```
두 책이 책장에 나란히 있어요.

책A: [====A====]
책B:              [====B====]

→ A의 오른쪽 끝이 B의 왼쪽 끝보다 왼쪽에 있네요?
→ 안 부딪쳤어요!

책A: [====A====]
책B:      [====B====]

→ 겹쳤네요! 부딪쳤어요!
```

#### 코드로 보기:
```cpp
// 1단계: 네모의 모서리 좌표 구하기
SrcMin = 중심 - 반크기;  // 왼쪽 하단
SrcMax = 중심 + 반크기;  // 오른쪽 상단

// 2단계: X축 검사
if (SrcMin.x > DestMax.x)  // A가 B보다 완전히 오른쪽?
    return false;  // 안 부딪침!

if (DestMin.x > SrcMax.x)  // B가 A보다 완전히 오른쪽?
    return false;  // 안 부딪침!

// 3단계: Y축도 똑같이 검사

// 4단계: 모두 통과하면 부딪친 것!
```

### 🔄 경우 2: 회전한 네모 (OBB)

**OBB = Oriented Bounding Box = 방향이 있는 상자**
→ "회전한 네모"라고 생각하세요!

#### 왜 복잡해지나?
```
회전 안 한 네모:
┌─────┐
│     │  → 가로, 세로만 비교하면 끝!
└─────┘

회전한 네모:
    ╱──╲
   ╱    ╲  → 어느 방향으로 비교해야 할지 모름!
  ╱      ╲
```

#### 핵심 아이디어: 분리축 정리 (SAT)
```
"여러 방향에서 봤을 때 멀리 떨어져 있으면 안 부딪친 거야!"
```

**비유로 이해하기:**
```
두 사람이 운동장에 서 있어요.
부딪쳤는지 어떻게 확인할까요?

방법: 여러 방향에서 확인
1. "정면에서 봤을 때 떨어져 있나?"
2. "왼쪽에서 봤을 때 떨어져 있나?"
3. "오른쪽에서 봤을 때 떨어져 있나?"
4. "위에서 봤을 때 떨어져 있나?"

→ 한 방향이라도 떨어져 있으면 안 부딪친 것!
```

#### 4개 방향 검사:
```
네모A의 X축 방향으로 봤을 때
네모A의 Y축 방향으로 봤을 때
네모B의 X축 방향으로 봤을 때
네모B의 Y축 방향으로 봤을 때

→ 4개 중 하나라도 분리되어 있으면 안 부딪침!
→ 모두 겹치면 부딪침!
```

#### 투영(Projection)이란?
```
실생활 예시: 손전등 그림자

손전등을 비추면 물체의 그림자가 생기죠?
그 그림자의 길이가 바로 "투영"이에요.

손 ───→ 빛 ───→ 벽에 그림자
              (그림자 크기 = 투영 길이)
```

#### AxisProjection 함수 쉽게 이해하기:
```cpp
bool AxisProjection(...)
{
    // 1. 두 네모 중심 사이의 거리를 특정 방향으로 투영
    float 중심거리 = abs(CenterLine.Dot(Axis));

    // 2. 네모B를 같은 방향으로 투영한 크기
    float 네모B크기 = (B의 너비 투영) + (B의 높이 투영);

    // 3. 비교
    if (네모A크기 + 네모B크기 > 중심거리)
        return true;  // 겹침!
    else
        return false; // 분리됨!
}
```

**그림으로 이해:**
```
특정 축에 투영:

[--A--]        [--B--]
   |--거리--|

네모 크기의 합 > 거리 → 겹침!

[--A--]
      [--B--]
   |--거리--|

네모 크기의 합 < 거리 → 분리!
```

## 2. 원 vs 원 충돌

### 🎯 이건 진짜 쉬워요!

```
두 원의 중심 사이 거리 vs 반지름의 합

거리 <= 반지름1 + 반지름2 → 부딪침!
거리 > 반지름1 + 반지름2 → 안 부딪침!
```

### 생활 예시:
```
두 사람이 서 있어요.

A의 팔 길이: 1m
B의 팔 길이: 1m
두 사람 사이 거리: 3m

→ 1 + 1 = 2m < 3m
→ 팔을 뻗어도 안 닿아요! (안 부딪침)

두 사람 사이 거리: 1.5m

→ 1 + 1 = 2m > 1.5m
→ 팔을 뻗으면 닿아요! (부딪침)
```

### 코드:
```cpp
// 두 원의 중심 사이 거리 계산
float Distance = 원A중심.Distance(원B중심);

// 반지름의 합과 비교
if (Distance > 원A반지름 + 원B반지름)
    return false;  // 안 부딪침!
else
    return true;   // 부딪침!
```

## 3. 네모 vs 원 충돌

### 🤔 조금 복잡한데, 쪼개서 생각하면 쉬워요!

#### 핵심 아이디어:
```
"여러 방향에서 봤을 때 떨어져 있나 확인!"
```

### 3가지 방향 검사:

#### 1. 원 → 네모 방향
```
원에서 네모를 바라보는 방향으로 투영
→ 이 방향에서 떨어져 있나?
```

#### 2. 네모의 X축 방향
```
네모의 가로 방향으로 투영
→ 이 방향에서 떨어져 있나?
```

#### 3. 네모의 Y축 방향
```
네모의 세로 방향으로 투영
→ 이 방향에서 떨어져 있나?
```

### 생활 예시:
```
상자와 공이 있어요.

1. "상자에서 공을 봤을 때 멀리 있나?"
2. "상자의 가로 방향으로 봤을 때 공이 옆에 있나?"
3. "상자의 세로 방향으로 봤을 때 공이 위아래에 있나?"

→ 3가지 모두 가까우면 부딪친 것!
```

## 4. 네모 vs 선 충돌

### 📏 2단계 전략!

#### 전략 1: 선의 끝점 검사
```
선의 시작점이나 끝점이 네모 안에 들어갔나?
→ 들어갔으면 무조건 부딪침!
```

**생활 예시:**
```
상자 안에 막대기를 넣어요.

막대기 끝이 상자 안에 있나요?
→ 네! → 부딪친 거예요!
```

#### 전략 2: 변과 교차 검사
```
선이 네모의 4개 변 중 하나와 교차하나?
```

**그림으로 이해:**
```
상황 1: 끝점이 안에 있음
┌─────┐
│  /  │  ← 선의 끝이 안에!
│ /   │
└─────┘

상황 2: 관통
    /
   /
  /
 / ┌─────┐
───│─────│─  ← 선이 변과 교차!
   └─────┘
```

### 점이 네모 안에 있는지 검사:
```cpp
// 점에서 네모 중심까지의 벡터를 만들어요
FVector3 CenterLine = Point - Box.Center;

// 네모의 X축 방향으로 투영해요
float Dist = abs(CenterLine.Dot(Box.Axis[X]));

// 투영한 거리가 네모의 반너비보다 크면 밖에 있어요!
if (Dist > Box.HalfSize.x)
    return false;  // 밖에 있음!

// Y축도 똑같이 검사
```

**비유:**
```
책상 위에 점이 있어요.

1. "책상 중심에서 가로로 얼마나 떨어져 있나?"
   → 책상 너비의 반보다 멀면 밖에 있음!

2. "책상 중심에서 세로로 얼마나 떨어져 있나?"
   → 책상 높이의 반보다 멀면 밖에 있음!

→ 둘 다 안쪽이면 책상 위에 있음!
```

## 5. 원 vs 선 충돌

### 🎯 이차방정식? 겁먹지 마세요!

#### 핵심 아이디어:
```
"선이 원을 관통하는 점을 찾는 거예요!"
```

### 실생활 비유:
```
원형 터널에 막대기를 넣어요.
막대기가 터널을 관통하나요?

1. 막대기가 터널에 닿는 점이 몇 개?
   - 0개: 안 닿음 (충돌 X)
   - 1개: 딱 스치고 지나감 (충돌!)
   - 2개: 관통함 (충돌!)

2. 그 점들이 막대기 범위 안에 있나요?
   - 있으면 충돌!
   - 없으면 충돌 X
```

### 과정 설명 (수학 없이):

#### 1단계: 선의 방향과 길이 구하기
```cpp
FVector3 Dir = Line.End - Line.Start;  // 선의 방향
float LineLength = Dir.Length();       // 선의 길이
Dir.Normalize();                       // 방향만 남기기
```

**비유:** 화살을 쏘는데, 화살이 어디로 날아가는지(방향)와 얼마나 멀리 날아가는지(길이)를 알아내는 거예요.

#### 2단계: 교점까지의 거리 계산
```cpp
// 복잡한 공식이 나오지만, 하는 일은 간단해요:
// "선 위의 어느 지점에서 원과 만나는지 거리를 계산"

float t1 = (-b + Det) / 2.f;  // 첫 번째 교점까지 거리
float t2 = (-b - Det) / 2.f;  // 두 번째 교점까지 거리
```

**비유:**
```
선의 시작점부터:
- t1 = 5m 지점에서 원과 만남
- t2 = 10m 지점에서 원과 만남
```

#### 3단계: 교점이 선분 범위 안에 있나?
```cpp
// 선의 길이가 7m인데
// t1 = 5m → 선분 위에 있음! (충돌!)
// t2 = 10m → 선분 밖! (무시)
```

### 특수 케이스: 선이 원 안에 쏙 들어간 경우
```
    ●────●  ← 선 전체가 원 안!
  ╱        ╲
 ╱          ╲
●            ●

→ 이것도 충돌이에요!
```

## 6. 선 vs 선 충돌

### ✂️ 두 선이 교차하나요?

#### 핵심 아이디어: CCW 알고리즘
**CCW = Counter Clock Wise = 반시계방향**

### 엄청 쉬운 원리:

```
선AB와 선CD가 교차하려면?

1. C와 D가 선AB의 양쪽에 있어야 함
2. A와 B가 선CD의 양쪽에 있어야 함
```

### 생활 예시:
```
가위로 종이를 자르는 걸 생각해보세요.

가위날A: ───
가위날B:    ───

가위를 닫으면 교차하죠? 왜요?
→ 가위날A의 양 끝이 가위날B의 양쪽에 있으니까!
```

### CCW가 하는 일:
```
점 3개(A, B, C)가 있을 때:

A ──→ B ──→ C가
- 왼쪽으로 꺾이나? (반시계방향) → 양수
- 오른쪽으로 꺾이나? (시계방향) → 음수
- 일직선이나? → 0
```

**실생활 비유:**
```
지도에서 길을 따라 가요.

출발지 → 중간 → 목적지

중간 지점에서 왼쪽으로 꺾었나요? 오른쪽으로 꺾었나요?
→ 이걸 알아내는 게 CCW!
```

### 교차 판정:
```cpp
int ccw1 = CCW2D(A, B, C);  // C가 선AB의 어느 쪽?
int ccw2 = CCW2D(A, B, D);  // D가 선AB의 어느 쪽?

if (ccw1 * ccw2 < 0)  // 부호가 다르다 = 양쪽에 있다!
    // C와 D가 선AB의 양쪽에 있음!
```

**비유:**
```
도로 중앙선을 생각해보세요.

점C: 도로 왼쪽 → ccw1 = 양수
점D: 도로 오른쪽 → ccw2 = 음수

양수 × 음수 = 음수 (< 0)
→ C와 D가 도로 양쪽에 있네요!
→ 선CD는 도로를 가로지릅니다! (교차!)
```

### 교점 계산 (크래머 공식):
```
수학 공식은 복잡하지만, 하는 일은 간단해요:
"두 선이 만나는 정확한 지점(x, y 좌표)을 계산"
```

## 🎓 핵심 정리

### 1. 네모 vs 네모
```
회전 없음 (AABB): 가로, 세로만 비교
회전 있음 (OBB): 4개 방향에서 투영해서 비교
```

### 2. 원 vs 원
```
중심 사이 거리 vs 반지름 합 비교
```

### 3. 네모 vs 원
```
3개 방향(원→네모, 네모X축, 네모Y축)에서 투영 비교
```

### 4. 네모 vs 선
```
1. 선 끝점이 네모 안에 있나?
2. 선이 네모의 변과 교차하나?
```

### 5. 원 vs 선
```
선이 원과 만나는 점을 계산
→ 그 점이 선분 범위 안에 있나?
```

### 6. 선 vs 선
```
CCW 알고리즘:
→ 서로의 끝점이 상대 선의 양쪽에 있나?
```

## 💡 꿀팁

### 투영(Projection)을 이해하는 가장 쉬운 방법:
```
햇빛과 그림자를 생각하세요!

물체 ───→ 햇빛 ───→ 그림자
                  (투영!)
```

### 내적(Dot)을 이해하는 가장 쉬운 방법:
```
"이 방향으로 얼마나 멀리 있어?"

A.Dot(B) = A를 B 방향으로 투영한 길이
```

### 외적(Cross)을 이해하는 가장 쉬운 방법:
```
"왼쪽? 오른쪽?"

시계방향이면 음수
반시계방향이면 양수
```

## 🎯 마무리

수학이 어려워 보여도, 결국 하는 일은 간단해요:

1. **거리 재기**: 얼마나 떨어져 있나?
2. **방향 보기**: 어느 쪽에 있나?
3. **비교하기**: 부딪치나 안 부딪치나?

이 3가지만 이해하면 모든 충돌 알고리즘을 이해할 수 있어요!

**기억하세요:**
- AABB: 회전 없는 네모 (가장 쉬움!)
- OBB: 회전하는 네모 (투영 필요)
- SAT: 여러 방향에서 확인
- CCW: 왼쪽? 오른쪽?
- 투영: 그림자 길이

수포자도 이해할 수 있어요! 화이팅! 🚀
