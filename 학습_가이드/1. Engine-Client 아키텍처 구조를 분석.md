● 프로젝트의 Engine-Client 정적 라이브러리 아키텍처를 분석했습니다. 자세한 구조는 다음과 같습니다:

  📁 프로젝트 구조

  GameEngine/
  ├── GameEngine/              # 엔진 소스 코드 (→ .lib로 컴파일)
  │   ├── GameEngine.vcxproj   # 정적 라이브러리 프로젝트
  │   ├── Asset/, Component/, Object/, Render/, World/
  │   └── Copy.bat             # 빌드 후 헤더 복사 스크립트
  │
  ├── Engine/                  # 공개 API 폴더
  │   ├── Binary/              # 컴파일된 .lib 파일
  │   │   ├── GameEngine_Debug.lib  (40.1MB)
  │   │   └── GameEngine.lib        (Release)
  │   └── Include/             # 공개 헤더 파일들
  │
  ├── Client/                  # 클라이언트 애플리케이션
  │   ├── Client.vcxproj       # 실행 파일 프로젝트
  │   └── main.cpp             # 엔트리 포인트
  │
  └── Binary/
      └── Client_Debug.exe     # 최종 실행 파일

  🔧 빌드 구성

  1. Engine 프로젝트 설정 (GameEngine/GameEngine.vcxproj)

  <ConfigurationType>StaticLibrary</ConfigurationType>

  - 타입: 정적 라이브러리 (모든 구성)
  - 출력: Engine/Binary/GameEngine_Debug.lib
  - 중간 파일: Obj/GameEngine/*.obj
  - 빌드 후 작업: Copy.bat 실행

  2. Copy.bat 스크립트

  xcopy .\*.h .\..\Engine\Include\ /D /Y /s
  xcopy .\*.inl .\..\Engine\Include\ /D /Y /s
  xcopy .\..\Engine\Binary\EngineAsset\*.* .\..\Binary\EngineAsset\ /D /Y /s

  엔진 소스에서 공개 API 폴더로 헤더 파일을 자동 복사합니다.

  3. Client 프로젝트 설정 (Client/Client.vcxproj)

  <IncludePath>../Engine/Include/;$(IncludePath)</IncludePath>
  <LibraryPath>../Engine/Binary/;$(LibraryPath)</LibraryPath>

  🔗 연결 메커니즘

  Client에서의 명시적 링킹 (Client/main.cpp:14-22)

  #ifdef _DEBUG
  #pragma comment(lib, "GameEngine_Debug.lib")
  #else
  #pragma comment(lib, "GameEngine.lib")
  #endif

  이 #pragma comment 지시문이 정적 라이브러리를 링크하는 핵심입니다.

  🎯 핵심 아키텍처 특징

  1. 헤더 분리 전략:
    - 소스: GameEngine/
    - 공개 API: Engine/Include/ (자동 미러링)
  2. 빌드 의존성: 솔루션 레벨에서 Client → GameEngine 의존성 설정
  3. 구성별 라이브러리:
    - Debug: GameEngine_Debug.lib (디버그 심볼 포함)
    - Release: GameEngine.lib (최적화)
  4. 정적 링킹의 장점:
    - 단일 실행 파일 배포
    - DLL 의존성 없음
    - 링커가 미사용 코드 제거 가능
    - 전체 프로그램 최적화 가능

  이 구조는 엔진과 클라이언트 코드를 깔끔하게 분리하면서도 단일 실행 파일 배포 모델을 유지하는 전형적인 게임 엔진 아키텍처입니다.
