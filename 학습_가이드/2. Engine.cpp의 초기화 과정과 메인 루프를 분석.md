  🔄 메인 루프 (CEngine::Run)

  윈도우 메시지 펌프 (90-122라인)

  int CEngine::Run()
  {
      MSG msg = {};

      while (mLoop)  // ← 게임 실행 플래그
      {
          if (PeekMessage(&msg, nullptr, 0, 0, PM_REMOVE))
          {
              // 메시지가 있을 때: 윈도우 메시지 처리
              TranslateMessage(&msg);  // 키 입력 → 문자 변환
              DispatchMessage(&msg);   // WndProc 호출
          }
          else
          {
              // 메시지가 없을 때: 게임 로직 실행
              Logic();
          }
      }

      return (int)msg.wParam;
  }

  PeekMessage vs GetMessage:
  - GetMessage: 메시지가 없으면 대기 (옛날 방식)
  - PeekMessage: 메시지가 없으면 즉시 반환 → 게임 루프에 적합!

  2단계 업데이트 구조

  1. Update: 일반 업데이트

    - 물리, 애니메이션, 입력 처리 등
  2. PostUpdate: 후처리 업데이트

    - 삭제 대기 객체 정리 등

  🔑 핵심 포인트

  1. 초기화 순서가 중요: Device → RenderManager → AssetManager 순서는 의존성 때문
  2. 메시지 펌프 최적화: PeekMessage로 메시지 없을 때 즉시 게임 로직 실행
  3. 고정된 업데이트 순서: Timer → Update → PostUpdate → Render
  4. 싱글톤 패턴: 모든 관리자가 GetInst() 사용
  5. 종료 메커니즘: WndProc에서 WM_DESTROY 받으면 mLoop = false (250라인)
