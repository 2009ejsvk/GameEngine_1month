  1️⃣3️⃣ 실제 Draw Call (Mesh.cpp:55-92)

  void CMesh::Render()
  {
      UINT Stride = mVB.Size;   // 정점 하나의 크기
      UINT Offset = 0;

      // 1. Primitive Topology 설정
      mContext->IASetPrimitiveTopology(mPrimitive);
      // D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST (삼각형 리스트)

      // 2. Vertex Buffer 바인딩 (Input Assembler 스테이지)
      mContext->IASetVertexBuffers(0, 1, &mVB.Buffer, &Stride, &Offset);

      // 3. Index Buffer 바인딩
      mContext->IASetIndexBuffer(
          mMeshSlot[i]->IndexBuffer.Buffer,
          mMeshSlot[i]->IndexBuffer.Fmt, 0);

      // 4. Draw Call 실행!
      mContext->DrawIndexed(
          mMeshSlot[i]->IndexBuffer.Count,  // 인덱스 개수
          0,  // 시작 인덱스
          0); // 정점 오프셋
  }

  DrawIndexed가 실행되면:
  - GPU가 Vertex Buffer에서 정점 읽기
  - Index Buffer를 참조하여 삼각형 구성
  - Vertex Shader 실행 → 각 정점 변환
  - Rasterization → 픽셀 생성
  - Pixel Shader 실행 → 각 픽셀 색상 계산
  - Depth Test → 앞/뒤 판정
  - Render Target에 픽셀 쓰기

  📊 전체 파이프라인 다이어그램

  ┌──────────────────────────────────────────────────────────────┐
  │                 DIRECTX 11 RENDERING PIPELINE                 │
  └──────────────────────────────────────────────────────────────┘

  [초기화 - 한 번만 실행]
  ────────────────────────────────────────────────────────────────
  1. D3D11CreateDevice
     └→ mDevice, mContext 생성

  2. CreateSwapChain
     └→ 백버퍼 + 프론트 버퍼 (더블 버퍼링)

  3. CreateRenderTargetView
     └→ 백버퍼에 그릴 수 있는 뷰

  4. CreateDepthStencilView
     └→ 깊이 테스트용 버퍼

  5. RSSetViewports
     └→ 화면 영역 정의

  6. D3DCompileFromFile + CreateVertexShader
     └→ HLSL → Vertex Shader 컴파일

  7. D3DCompileFromFile + CreatePixelShader
     └→ HLSL → Pixel Shader 컴파일

  8. CreateInputLayout
     └→ 정점 구조 정의

  9. CreateBuffer (Vertex Buffer)
     └→ GPU 메모리에 정점 데이터 업로드

  10. CreateBuffer (Index Buffer)
      └→ GPU 메모리에 인덱스 데이터 업로드

  [매 프레임 - 60fps라면 초당 60번 실행]
  ────────────────────────────────────────────────────────────────
  BeginRender()
    ├─ ClearRenderTargetView     ← 백버퍼 클리어
    ├─ ClearDepthStencilView     ← 깊이 버퍼 클리어
    └─ OMSetRenderTargets        ← 렌더 타겟 바인딩

  For each GameObject:
    ├─ UpdateBuffer (Transform)  ← World/View/Proj 행렬 전송
    ├─ VSSetShader              ← Vertex Shader 설정
    ├─ PSSetShader              ← Pixel Shader 설정
    ├─ IASetInputLayout         ← Input Layout 설정
    ├─ UpdateBuffer (Material)   ← 색상, 텍스처 전송
    ├─ IASetPrimitiveTopology   ← Triangle List 설정
    ├─ IASetVertexBuffers       ← 정점 버퍼 바인딩
    ├─ IASetIndexBuffer         ← 인덱스 버퍼 바인딩
    │
    └─ DrawIndexed()            ← GPU 렌더링 실행!
         │
         ├─ [Input Assembler (IA)]
         │    └→ 정점 데이터 조립
         │
         ├─ [Vertex Shader (VS)]
         │    └→ 각 정점 변환 (World * View * Proj)
         │
         ├─ [Rasterizer (RS)]
         │    └→ 삼각형 → 픽셀 변환
         │
         ├─ [Pixel Shader (PS)]
         │    └→ 각 픽셀 색상 계산
         │
         ├─ [Output Merger (OM)]
         │    ├─ Depth Test (깊이 테스트)
         │    ├─ Blend (투명도 블렌딩)
         │    └─ Render Target에 쓰기
         │
         └─ [Render Target]
              └→ 백버퍼에 픽셀 저장

  EndRender()
    └─ Present()                ← 백버퍼 ↔ 프론트 버퍼 스왑
         └→ 화면에 표시! ✨

  🔑 핵심 개념 정리

  고정 기능 파이프라인 vs 프로그래머블 파이프라인

  | 스테이지        | 타입         | 설명                  |
  |-----------------|--------------|-----------------------|
  | Input Assembler | 고정         | 정점/인덱스 버퍼 읽기 |
  | Vertex Shader   | 프로그래머블 | HLSL 코드로 정점 변환 |
  | Rasterizer      | 고정         | 삼각형 → 픽셀 변환    |
  | Pixel Shader    | 프로그래머블 | HLSL 코드로 색상 계산 |
  | Output Merger   | 고정         | 깊이 테스트, 블렌딩   |

  CPU와 GPU의 역할 분담

  CPU 역할 (Device.cpp, MeshComponent.cpp):
  - 리소스 생성 (CreateBuffer, CreateShader)
  - 파이프라인 설정 (SetShader, IASetVertexBuffers)
  - Draw Call 발행 (DrawIndexed)

  GPU 역할:
  - Vertex Shader 실행 (병렬 처리)
  - Rasterization
  - Pixel Shader 실행 (병렬 처리)
  - 최종 픽셀 출력

  왜 이렇게 복잡할까?

  1. 유연성: 셰이더를 바꾸면 완전히 다른 렌더링 가능
  2. 성능: GPU 병렬 처리로 수백만 정점을 실시간 처리
  3. 재사용성: 한 번 만든 버퍼를 여러 번 그릴 수 있음
