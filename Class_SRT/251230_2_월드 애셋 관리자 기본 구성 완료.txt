그럼 나머지 친구들도 일단은 같은 방식으로 만들어주면 좋을 것 같아요.  어... 쉐이더, 얘는 머티리얼하고 텍스처, 애니메이션 2D로 할게요.  그래서 2번부터 다 만들어주고, 쉐이더 매니저에서 지원해주고 있던 함수들도 여기서 똑같이 다 지원하면 될 것 같아요.  이제 쉐이더 매니저의 Create Buffer, Find CBuffer, Find Shader 같은 기능들을 여기서도 똑같이 템플릿 형태로 만들어주도록 할게요.  자, 일단은 버퍼랑 쉐이더부터 만들어줄게요. Create Buffer 같은 경우에는 얘랑 거의 비슷해요.  거의 비슷한데 좀 수정합시다. 자, 일단은 여기서 쉐이더 매니저가 필요해요.  그러면 쉐이더 매니저가 남의 거라서 가지고 올게요. 얘는 CBuffer고, 인자로 들어오는 이름을 합쳐서 하나 만들어주고...  Create CBuffer... 키, 사이즈, 레지스터, 그 다음에 쉐이더 버퍼, 이렇게 넣어서 만들어주면 되겠죠?  SM 매니저에서 이걸 찾았는데 없어요. 추가가 안 되어있을 경우라면 쉐이더 매니저에서 Find CBuffer 해가지고 키로 탐색합니다.  똑같죠? 이제 함수랑 인자만 조금 다를 뿐인 거고, Find를 하는 것도 메쉬에 있는 거랑 동일해요. 그대로 들고 와서 이렇게요.  얘는 상수 버퍼, 아까 CBuffer라고 이름 지었죠? Name 찾고 추가 안 되어있을 경우에는 쉐이더 매니저에서 꺼내볼 겁니다.  Find CBuffer... 얘가 있을 경우라면 추가해 줄게요. 그리고 Constant Buffer로 다운 캐스팅해서 리턴합니다.  여기 쉐이더도 마찬가지예요. 쉐이더 네임으로 찾고, 없을 경우엔 똑같이 쉐이더 매니저를 이용해 Find Shader로 찾습니다.  자, 얘가 있을 경우에는 쉐이더로 추가하고, 밑에 다이나믹 캐스트는 쉐이더로 리턴합니다. 자, 여기까지는 됐고.  이제는 쉐이더 쪽을 봐야 되는데, 이거는 저희 Create 하는 거랑 거의 비슷해서... 쉐이더 매니저는 여기서 들고 있어야겠네요.  에셋들을 인클루드하는 건 헤더로 옮겨주고, 쉐이더 매니저를 꺼내놓고요. 있을 경우에는 똑같은 게 있으니까 쉐이더를 못 만드죠.  그러면 일단은 키부터 만들어야 되겠네요. 쉐이더 언더바(...)로 탐색해서 있을 경우는 못 만듭니다.  만약 없을 경우라면 키랑 패스 네임(Path Name)을 넣어서 쉐이더를 만들어요. 하지만 이게 만약에 실패했다면 Return False를 하면 되겠죠.  하지만 성공했다면, 여기서 SM Map에서 Find하고 만약에 없다면...  쉐이더 매니저로부터 Find Shader로 추가해 드리도록 할게요. 여기서 이것도 제거하고... 됐다.  똑같이 갖다 쓴 겁니다. 쉐이더랑 상수 버퍼도 끝났어요. 다음은 머티리얼인데, 얘는 지금 머티리얼 매니저를 따로 안 쓰고 있죠.  머티리얼 같은 경우에는 저희가 메쉬가 가지고 있으면서 직접 구성해서 사용하고 있어요. 미리 만들어 놓고 가져다 쓰는 게 아니라요.  일단 얘는 냅둡니다. 여기 텍스처... 샘플러 스테이트라든지 텍스처, 이 두 가지를 모두 가지고 있기 때문에 여기에다가 넣어요.  샘플러 같은 경우에는 샘플러 스테이트가 따로 있죠. 얘는 에셋이 아니거든요. 그래서 샘플러 쪽은 무시하고 텍스처 쪽만 볼 거예요.  Load Texture, Find Texture 여기까지만. 어차피 샘플러는 처음에 한 번만 넣어놓고 말기 때문에 그대로 둘 겁니다.  텍스처는 어떤 월드에서든 다 쓰게 될 거예요. 그래서 샘플러 세팅은 공용으로 쓰고 있으니까 이대로 두고, Load Texture부터 Find Texture까지만 가져옵니다.  이렇게 해서 로드 함수들을 싹 다 만들어주고 정리 좀 해줄게요.  Create CBuffer 한 거 그대로 들고 와서 똑같이 만들 건데, 다만 매니저가 쉐이더 매니저가 아니라 텍스처 매니저를 꺼내야겠죠?  텍스처 매니저로부터 로드 텍스처... 키, 파일 네임, 패스 네임을 넣습니다. 로그를 넣어 로드할 수 있게 만들고, Find로 키를 찾습니다.  없을 경우에 이 텍스처 매니저로부터 Find Texture 해서 추가해주겠다는 거예요. 그리고 함수 이름을 LoadTexFullPath로만 변경하시면 되겠죠.  그리고 밑에 벡터로 불러오는 것도 동일하게, 이름만 똑같잖아요. 그대로 넣어놓고 풀 패스도 벡터로 불러오는 것은 동일하게 처리합니다.  다만 여기서 Find Texture 하는 부분만 조금 수정해서, 텍스처 언더바 이름으로 찾고 텍스처 매니저로 꺼내보고 Find Texture를 합니다.  못 찾았을 때 추가하고 리턴, 그냥 다 똑같으니까요. 그리고 애니메이션 2D 갖고 올 때도 마찬가지예요.  Create Animation부터 애니메이션들 교체하는 것... 자, 그럼 여기까지를 World Asset으로 똑같이 만들어주고...  Create Animation도 똑같으니까 그대로 가져갑니다. 얘는 오히려 더 간단해요. 애니메이션 2D 매니저를 꺼내볼게요.  애니메이션 2D 매니저의 Create Animation으로 이 키 값을 그대로 넣어주면 되고요, 생성 실패하면 Return False.  그게 아니라면 키로 Find 해보고, 여기에 똑같은 게 없다면 애니메이션 2D 매니저에서 Find Animation 해서 찾아서 넣고 리턴합니다.  Find 같은 경우엔 그대로 넣고 올게요. 애니메이션 2D 언더바가 있기 때문에 얘를 넣어보고...  그다음에 애니메이션 2D 매니저에서 Find Animation 하고, 없으면 추가, 그게 아니면 리턴. 이렇게 처리해 놓을게요.  이거는 이제 텍스처 타입 지정을 한 거다 보니까 그냥 그대로 갖다 쓰면 될 것 같아요. CAnimation2D로 다이나믹 캐스트 해주고...  Return True인지 확인하고... 그럼 여기에다 지정한 Set Texture도 완전 동일하게 할 겁니다.  키 값으로 Find 그래놓고 Set Texture... 여기에다가 텍스처 지정해요.  자, 여기에 Set Texture라는 이 부분도 일단 애니메이션은 똑같이 찾아옵니다. 그리고 네임을 넣어가지고 Set Texture를 하고...  근데 이걸 이렇게 넣으면 SM 매니저에서 바로 찾아버리죠. 얘를 바로 찾아가지고 세팅을 해버리고 있어요.  근데 World Asset Manager에서 텍스처를 찾아도 상관이 없잖아요. 그러니까 여러 개를 찾아도 되잖아요.  그리고 이 이름 자체가 텍스처 언더바는 안 붙이고 이름만 그냥 똑같이 쓸 거예요. 저희에게 자동으로 찾아내고 있죠.  이렇게 벡터(Vector)로 꺼내놓을 겁니다. 그리고 얘는 텍스처를 로드하는 시스템이죠.  일단 애니메이션 2D 꺼내놓고 Load Texture를 할 겁니다.  만약에 텍스처 로드에 실패하면 False, 성공하면 Find Texture 찾아가고 그냥 집어넣어 버릴 거예요.  남아있는 것도 똑같으니까 Load Texture Full Path... 파일 이름만 벡터일 뿐인 거지 다 붙여넣기죠. 그냥 싹 다 같은 방식이라는 거예요.  그리고 Add Frame 같은 경우엔... 여기 보시면 Add Frame을 할 때 그냥 이걸 찾으려고 하고 있어요.  찾아요, 찾아요... 근데 그게 아니에요. 그러면 Add Frame, Start, Size 이것도 넣어가지고 추가...  그다음에 여기는 개수, 카운터 하나만 추가하면 되니까... 이러면 월드 단위로 Asset를 싹 다 모아가지고 관리하는 시스템을 만들게 될 거예요.  Return True를 빼먹었네... 됐다. 그래서 월드 단위로 Asset를 좀 한 곳에 모아가지고 관리하는 World Asset 관리자를 하나 만들었어요.  그래서 저희가 나중에 월드를 전환할 때도 A World와 B World가 서로 공유하는 Asset이면 메모리에 남겨 놓고 그냥 그대로 계승해서 쓸 수 있게끔 할 거고,  A에서는 쓰다가 B로 넘어가면서 갑자기 안 쓴다면, Asset을 제거해서 메모리를 확보해 줄 수 있는 도움이 될 것 같습니다.  그래서 그런 시스템을 만들려고 월드마다의 Asset을 관리하려고 따로 만들었어요.  물론 아까도 말씀드렸지만, 저희가 포트폴리오 수준에서는 사실 그 정도까지의 Asset을 사용하지는 않을 거기 때문에 메모리가 부족하거나 하는 경우는 없으실 거예요.  근데 실제 서비스하는 게임들 같은 경우에는 이런 메모리 관리가 굉장히 중요한 요소 중에 하나예요.  여러분들이 '아, 이 에셋들은 메모리가 많이 들어가니까 어떤 식으로 우리가 메모리를 관리를 해야 되겠구나'라는 개념이 있어야 돼요.  그렇기 때문에 우리한테 굳이 필요는 없지만, 지금 포폴 만들 때는 전혀 필요가 없는데도 불구하고 만드는 거예요.  회사에서는 중요한 요소 하나가 될 테니까... 자, 그래서...  일단 기본적인 World Asset 관리자를 만들어가지고 Asset을 관리할 수 있게끔 전해드렸습니다.
